# 音乐×队形工作流整改方案（Workflow Rectification Plan）

**版本基准**：v0.9.21 / build-32-dualmode · main `d4fe357`
**性质**：方案文档 + 现状审计。本轮**未改动任何应用代码**（js/*、index.html、css/*、scripts/*、dist 零变更）。
**证据目录**：`~/.zcode/workspace/default/wuzhen-e2e-lab/out/round51-audit/`（audit.json 全量量测 + 7 张截图）；审计脚本 `wuzhen-e2e-lab/round51-audit.mjs`（playwright 只读驾驶，复用 analysis-lib 真实 UI 路径建项/载乐）。

## 0. 用户反馈（权威需求）与结论摘要

用户四点反馈：
1. 音乐编辑应是**单独模式**，展开后**几乎占据所有 UI 空间**，编舞只占小部分；现状「音乐」tab 只是放大侧边栏，音乐编辑没用上这部分空间；
2. 正确工作流：**音乐编辑（多轨、多 clip 多节奏型）→ 节拍划分（乐段节拍 + 打 tag）→ 队形编排**；
3. **任意阶段都可调整所有元素**，且谁在被调整谁占大空间：音乐/节奏阶段=队形只做小 preview 供对齐；队形编排阶段=音乐浓缩为简单 UI（只留必要 tag 与节奏划分结果，不再多轨）；
4. 检查现状、给出整改方案、**清除冗余**、让工作流简洁直观。

**审计结论（一句话）**：现状「音乐模式」是一个**伪模式**——它只把舞台收窄到 320px，把省出来的横向空间（editor-main 的 **63%**）给了**右侧编舞属性面板**（队形/舞台/样式/编组页签），而真正的音乐编辑仍挤在底部 104px 条里（视口的 **12%**，其中纯剪辑 lane 仅 26px=3%）。空间分配与需求**完全倒挂**（证据 E-01）。此外存在轨头空 DOM 缺陷、打点入口在音乐模式消失、双入口冗余等 10 项问题（§1），冗余控件/面板/双入口共 **17 项**待清除或迁移（§3）。

## 2. 目标架构：双模式完整定义

### 2.0 工作流主轴

```
音乐编辑（多轨 clip，任意资产/节奏型）──→ 节拍划分（乐段节拍 + tag 标注）──→ 队形编排（块时长/走位）
        音乐模式（主区=多轨面）                音乐模式（同一视图，tag 道在上）        编舞模式（主区=舞台+块区）
                        两模式随时一键互切（M 键 / 顶栏 seg），互不丢状态（现状已保证）
```
音乐模式内部两步（剪辑、标拍）共用同一视图：多轨 lane 堆叠 + 尺规/tag 道常驻，只是用到的工具组不同——**不再为「节拍划分」单设视图**。

### 2.1 编舞模式（默认；几何与现状逐值一致）

- 主区不变：左队形列表 180px + 舞台 + 右属性面板 250px；块时长栏、块区 canvas、tag 道全保留（红线 E-12）。
- **音乐浓缩 UI**（替换现状整条「音乐与节拍」面板）：
  - `#music-strip` 收敛为**单行音乐摘要条**（高 ~30px）：`♪ 资产名 64.0s · BPM120 4/4 · [试听] [tag N 个 · 点击跳转列表] [编辑音乐 →]`；
  - 时间轴内**音频简单道 26px 保留但转只读**：显示波形缩影 + tag 旗 + 播放头（对齐参照），点击=seek、单击旗=跳转；**不再响应拖移/trim/右键编辑菜单**（右键仅留「在音乐模式中编辑」跳转项）——修复 E-10；
  - 多轨不可见：编舞模式恒单道合并呈示（现状行为保留，trackCount=1 分支不动）；
  - `[编辑音乐 →]` = `setUiMode('music')` 的显性入口（摘要条右侧，次按钮）。
- 编舞模式可调整的音乐元素：播放/试听、tag 跳转、BPM 只读呈示（修改需进音乐模式——BPM 是节拍划分产物，归音乐阶段）。

### 2.2 音乐模式（多轨编辑面占据主区）

- **lane 高推导**（音乐模式不再用固定公式）：`laneH = clamp((容器高 − 22 − 24 − 28 − 12×(n−1)) / n, 56, 120)`；`#tl-scroll{flex:1}` 由 flex 撑满，`totalHeightFor()` 音乐分支改为读容器实测高。1 轨=120px、2 轨=104px、4 轨=56px（860 高实测值）；轨多超出时 `#tl-body{overflow-y:auto}` 纵向滚动。
- **多轨 lane 形态**：沿用 lightmix 单轨精简样式——每轨 = lane（波形 clip 盒）+ 轨头 140px（现 120px 升级：名/音量/静音 + 空置「1 个剪辑/空轨」行）；N 轨上限沿用 **4**（TRACK_MAX 不变）。
#### 2.2.1 节奏划分轨（音乐模式的专用轨——音乐→队形的桥梁）

节奏划分不是 tag 道的附属功能，而是音乐模式内的**独立专用轨**（升级 tag 道：24→28px），承载「划分乐段 → 对齐队形」的桥梁职责。三个能力：

**① 自动划分（一键落段）**——音乐工具条「自动划分 ▸」下拉三来源：
| 来源 | 行为 |
|---|---|
| 均分 N 段 | 按 totalBeats/N 生成 N 个段起点 tag（N=输入，默认按 8 的倍数） |
| 按小节规则 | 每 8 拍（副歌）/16 拍（主歌）自动落标——规则表可后续接 skill DENSITY_RULES |
| 导入段落表 | 粘贴/导入「前奏8 主歌32 副歌32…」文本 → 解析落 tag（复用 skill analyze-music 解析） |

**② 便捷修改（段级直接操作）**：
- **拖段边界**：相邻段伸缩，拍位吸附到小节线（磁吸候选已有）；
- **双击段**：内联重命名（同 tag 命名交互）；
- **段右键**：于此拆分 / 合并相邻 / 删除 / 换色（段色板 4 色）；
- **单击段**：播放头跳段起点（快速索引的动作面）；
- 段呈示：色块（4 色循环）+ 名称胶囊，选中段高亮描边。

**③ 快速索引（跳转与总览）**：
- 索引弹出列表（tag 道左端列表钮或 ⌘）：段名 + 拍位 + 秒位，**点击跳转**、↑↓ 键盘步进；
- 编舞模式摘要条保留「tag N 个 · 点击跳转列表」入口（同列表）。

数据模型不变：段=相邻 tags 派生区间（`[tags[i].beat, tags[i+1].beat)`），存储仍是 `timeline.tags`（起点标记模型）——自动划分=批量写 tags，零新 schema。

**③b 编舞模式的浓缩呈现（刻度线形式）**：
- 尺规与音频简单道上，段边界以**强调刻度线**绘制（粗于普通拍线、段色着色）+ 段名小字标注（空间不足悬浮）；
- 摘要条 tag 计数/列表入口跳转不变；
- 纯绘制层增强，零交互变化、零基础体验影响（红线 E-12 不动）。
- **队形 mini-preview**（占 ~15-20% 空间，280/1360≈20%）：只读小画布渲染当前队形（复用 `drawScene` minimal 模式，同 `#formation-index` 缩略图路径），随播放头同步（player.onTick 已驱动 formationIndex → render 钩子重画）；含当前块 保持/过渡 ±1 拍步进（复用 `stepBlock`）与「对齐到播放头」——落实「任意阶段可调整」的最小集；**编舞块区 canvas 完全隐藏**（现状已隐藏，保持）。
- **隐藏清单**（音乐模式）：`#left-panel`、`#stage-col`（舞台工具+舞台 canvas+E-02 全套残件）、`#right-panel`、移动端 `#mobile-tabs`。

## 3. 冗余清除清单（逐项处置）

> 处置口径：**删除**=连 DOM 带逻辑退役；**迁移**=控件移动归属（功能不丢）；**合并**=多入口并一；**保留**=不动。

| # | 对象（现状位置） | 处置 | 去向/理由 |
|---|---|---|---|
| C1 | 「音乐与节拍」折叠面板 `#audio-disc` 整体（底部，两模式同版） | **删除**（拆分后退役） | 职责拆到 C2-C6 三个归属；消除 E-03 混杂 |
| C2 | 载入音乐 `#btn-load-audio` / 媒体库 `#btn-media-library` / 按队形段自动切 `#btn-auto-split` | **迁移** | 音乐工具条「资产组」（音乐模式专属；空态 `#tl-audio-empty` 同步并入） |

### 4.3 节奏型/变速：不引入 tempoMap（引用 r2 实证）
`docs/optimization-plan-r2.md` §2.1 已钉死：单值 BPM 线性模型下 60s 双速曲（120→160）后半段拍线偏移累积 **9.875s/19.75 拍**，最佳拟合仍残 4.378s——**单值 BPM 对变速曲不可靠，任何折中两段都错**；§2.2 钉死 clip 引擎秒制天然免疫。据此音乐模式呈现建议（不新增复杂度）：
- **剪辑层维持秒制**（现状，不动）；**tag/块仍以拍位存储**（领域八拍语义不丢，r2 §3.3 裁定）；
- 拍/秒双刻度沿用现状 `tl-scale-toggle`（决策⑥），仅两处小改：①刻度记忆改**按模式分键**（`wuzhen:rulerScale.stage` / `.music`，缺省均=拍）；②音乐模式载入变速体检 toast（已有）追加「切秒刻度」动作钮，一键 `setRulerScale('sec')`；
- 变速对齐降级手段已有：Alt+←/→ 播放头秒步进 ±0.5s（main.js L2049-2058），说明书补一句即可；
- tempoMap（方案 C）继续**不立项**，触发条件不变（真实变速曲占比 + 用户拍板）。
