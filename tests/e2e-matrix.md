# 赛阵 E2E 手势测试计划 v3 —— 截图+DOM 双重验证体系

> **版本 v3（round14 起，产品语义裁定）**：① 舞对绑定（pairs）全面退役——项目数据不再有 `pairs` 字段，
> 编组（RTS 式选择辅助 `groups`）取而代之；② 合并单元样式收敛为两样式 `capsule` / `single`
> （`diamond`/`twin` 退役，旧数据载入时迁移为 capsule）。
> v2 的单元原子语义（round9）全部继承；v1/v2 计划中一切「舞对/舞伴/配对/组队/菱形/双圆」叙述作废。
>
> **强制规范：此后所有页面操作测试，每一条动线都必须同时通过截图验证与 DOM 验证。
> 只断言数据/元素的测试视为无效证据；只看截图不断言状态的测试视为不可复核。**
> 三层结构：L0 测试操作本身的有效性（与业务逻辑无关）→ L1 原语手势动线 → GR 编组动线 → L2 组合功能动线；
> R 组（单元语义）穿插于 L1 与 GR 之间。

## 0. 验证的四个层次（每个验证点都标注属于哪层）

| 标注 | 验证什么 | 实现手段 | 能发现的问题 |
|------|----------|----------|--------------|
| [STATE] | 应用数据/状态 | store 快照：selection、positions、merges、groups、history 深度、UI 开关 | 业务逻辑错误、状态机缺陷 |
| [DOM] | 结构与几何 | 元素存在性、querySelector 计数、getBoundingClientRect、事件 target | 弹窗未创建、按钮不可点、节点丢失 |
| [PIXEL] | 画布位图真实渲染 | canvas getImageData 在预期坐标采样颜色/形状 | 渲染逻辑错误（画了但画错位置/颜色）、位图未更新 |
| [SCREEN] | 合成器输出=人眼所见 | tab 截图 → PNG 注回页面 → createImageBitmap 解码 → 与实时画布位图逐像素对比 + 人工目检 | **合成器瓦片错位**（v1 轮实证过：DOM 单份、屏幕四份陈旧帧）、视觉层故障 |

**判定规则**：一条动线 PASS 当且仅当其全部验证点通过；任一 [SCREEN] 失败 = 环境故障，停止本轮并重建标签（这不是应用缺陷，但必须记录）；[PIXEL]/[DOM]/[STATE] 失败 = 应用缺陷，进入修复流程。

### 0.1 SCREEN 自动比对算法（消除"人眼不可用"问题）
1. 截取整页 PNG（base64）；
2. 注回页面：`createImageBitmap(blob)` → 绘入 OffscreenCanvas；
3. 按 `canvas.getBoundingClientRect()` 与 `devicePixelRatio` 换算出舞台画布在截图中对应的像素区域；
4. 与实时 `cv.getImageData()` 同区域对比：颜色差异像素比 < 0.5% 判定"屏幕=位图"；
5. 同时对截图中弹窗/舞者预期区域做颜色采样，交叉验证 [PIXEL] 结论。

### 0.2 PIXEL 探针算法（画布位图断言）
- 舞者存在：预期圆心 3×3 均色与背景/网格基色的色距 > 阈值（基线启动时采样记录）；
- 选中高亮：选中舞者外圈出现主题高亮色；
- 单元徽标呈示（capsule）：两合并舞者中点采样到徽标双半填充色，且两人原圆心不再出现独立圆点色；
- 单元徽标呈示（single）：中点处仍为一个圆（取成员之一填充色，编号取小者）+ 半径 1.45r 的**虚线外环**
  呈**主题强调色**（浅色 `#0284c7` / 深色 `#38bdf8`）+ 右上角 **×2 角标**（同强调色）；原圆心不再有第二独立圆；
- 浮窗渲染：unit-menu DOM rect 中心对应画布区域无要求（弹窗是 DOM 不是画布）——其视觉验证走 [SCREEN]。

## 2. L1 —— 原语手势动线（17 条 × 硬件矩阵）

**硬件矩阵**：M=桌面鼠标全量；T=触摸全量；P=笔（P-d 子集）；每条编号后缀标注适用硬件。
**布置基线**：真实 dancer id（禁改名）；12 舞者两行；snap 关闭（精确用例）+ snap 开启专项；视图 fit；每动线后断言指针零残留。
**单元原子语义（v2 继承，v3 不变）**：合并单元是一切操作的原子——点选/shift/多选/框选命中任一成员=整单元（两名成员）入选或移出；拖动任一成员=整单元同步位移（单人拉伸路径已删除，分离呈示不可经拖拽产生）；Escape/双指=整单元回滚。未合并舞者行为不变（D 组默认以未合并舞者为对象，单元原子性由 R 组专测）。
**v3 词汇表**：合并两舞者=「合并为单元」；单元浮窗标题=「合并单元」；样式按钮=「胶囊 / 单编号」；工具栏入口=「合并为单元 / 取消合并」（原 ⛓组对/✂拆对 已删）。

### D-01 单击选择 [M/T/P]
步骤：click 舞者 A 圆心（A 为未合并舞者）
- [STATE] selection==[A]；undo 栈不变
- 补充（单元原子语义）：若 A 属合并单元，则点选=整单元两人同时入选 selection==[A,B]（原子性抽查见 R-07）
- [PIXEL] A 圆心出现选中高亮色；其他舞者无高亮
- [SCREEN] 截图中 A 位置与位图一致（比对差异 <0.5%）
验证目标：最基本的选择语义 + 高亮渲染 + 屏幕真实可见。

### D-02 单击空白 [M/T]
步骤：click 空白点
- [STATE] selection 清空 ｜ [PIXEL] 全员高亮消失 ｜ [SCREEN] 同步
验证目标：取消选择的渲染与数据同步。

### D-03 Shift 多选/移出 [M]
步骤：shift+click E → shift+click E
- [STATE] 先 2 人后 1 人 ｜ [PIXEL] 高亮跟随 ｜ [SCREEN] 同步
验证目标：修饰键多选语义与视觉一致。

### D-04 双击合并单元 [M/T/P]
步骤：dblclick 已合并单元中点
- [STATE] 无数据变更 ｜ [DOM] 浮窗出现（v3 标题=「合并单元」，按钮含 拆开/胶囊/单编号/删除）且 rect 距单元 <150px ｜ [PIXEL] 无要求 ｜ [SCREEN] 弹窗视觉可见且位置与 rect 一致（截图采样弹窗边框色）
验证目标：双击触发单元浮窗，浮窗锚定在单元处且真实渲染。

### D-05 长按合并单元 [T/P]（mouse 长按明确不触发 → D-05n；桌面端入口=双击 D-04 / 右键 R-01）
步骤：press 700ms 位移 <12px
- [STATE] 无变更 ｜ [DOM] 浮窗出现（标题=「合并单元」）｜ [SCREEN] 可见
验证目标：长按时长/位移阈值的触摸端语义；桌面端确认**不**触发（负断言）。

### D-06 拖拽移动+松开 [M/T/P]
步骤：down → 3+ 渐进 move（每步 30ms）→ up 于目标点
- [STATE] 仅该舞者位移 delta（snap 关=精确值，开=网格对齐）；恰一条"移动舞者"历史
- [DOM] 松手点 hit 无弹窗（无重叠时）
- [PIXEL] 该舞者旧圆心回到基线色、新圆心出现舞者色
- [SCREEN] 拖拽终点截图与新位置一致
验证目标：拖拽全链（按下-移动-松开）的数据、渲染、屏幕三重一致——**这是用户报告"粘黏/不落位"的核心动线**。

### D-07 拖拽驻留合并 [M/T/P]
步骤：drag 至他人重叠点，dwellMs=1700（移动中停住，不松手）
- [STATE] 位移已提交（取消确认也保留）｜ [DOM] 弹窗在驻留期间出现（松手前；v3 标题=「合并为单元」，样式按钮=胶囊/单编号 两枚自动生成）｜ [PIXEL] — ｜ [SCREEN] 弹窗可见
验证目标：驻留触发时序；弹窗渲染时机。

### D-08 框选 [M]
步骤：空白处 down → 拖出矩形 → up
- [STATE] 矩形内全选 ｜ [PIXEL] 框选矩形蓝色边框在拖动中可见、松手消失 ｜ [SCREEN] 同步
验证目标：框选渲染与选择语义。

### D-09 双指捏合 [T]
步骤：两指从 120px 捏到 220px
- [STATE] scale 变化 |Δ|>1 ｜ [PIXEL] 舞者直径等比变大（采样半径）｜ [SCREEN] 同步
验证目标：缩放联动渲染。

### D-10 滚轮缩放 [M]
步骤：wheel ±240 于画布中心
- [STATE] scale ≥20% 变化 ｜ [PIXEL] 缩放锚点下舞台点不漂移 ｜ [SCREEN] 同步
验证目标：缩放锚点精度。

### D-11 平移 [M/T]
步骤：触摸/笔单指空白拖动=平移（位移<promoteM 抬起=点按清空选择，归 D-02）；桌面：中键按住空白拖动 或 空格按住+左键空白拖动=平移（左键空白拖动仍为框选，见 D-08）
- [STATE] view.ox/oy 变化；选择不变 ｜ [PIXEL] 全体舞者等量平移 ｜ [SCREEN] 同步
验证目标：平移不改数据、不改选择。

### D-12 Escape 取消 [M]
步骤：拖动中途 key Escape → 松手
- [STATE] 位置精确还原、undo 栈零增长 ｜ [PIXEL] 位图还原 ｜ [SCREEN] 同步
验证目标：取消路径的完整回滚。

### D-13 方向键 [M]
步骤：选中 → ArrowRight
- [STATE] snap 关=+0.1，开=对齐 0.5 ｜ [PIXEL] 新位置出现舞者色 ｜ [SCREEN] 同步
验证目标：键盘微调与吸附。

### D-14 朝向把手 [M]
步骤：单击舞者 → 拖动朝向把手
- [STATE] facing 更新、一条历史；不拖不动则零历史 ｜ [PIXEL] 朝向线转向 ｜ [SCREEN] 同步
验证目标：把手命中优先级与朝向渲染。（v3：「面向舞伴」朝向选项随 pairs 退役，统一朝向=面向观众/面向圆心。）

### D-15 撤销/重做 [M]
步骤：执行移动+合并后 Ctrl+Z ×N / Ctrl+Shift+Z ×N
- [STATE] 状态逐帧还原/重放 ｜ [PIXEL] 位图逐帧一致 ｜ [SCREEN] 同步
验证目标：历史栈与渲染联动。

### D-16 编辑锁 [M/T]
步骤：关编辑 → 全部手势尝试 → 面板操作 → 开编辑 → 复测
- [STATE] 关=舞者零位移零选择变更；面板可操作 ｜ [PIXEL] 位图不变 ｜ [SCREEN] 同步
验证目标：锁语义精确（只锁舞台舞者，不锁时间轴/面板）。

## 3.5 R 组 —— 单元语义动线（v2 引入，v3 词汇同步：统一上下文菜单 + 单元原子化）

**背景**：合并单元语义为「单元原子化 + 右键/长按统一上下文菜单」。三入口共用 .unit-menu 与
gestureMenuClosed 解锁路径：触摸/笔长按（合并=单元菜单；未合并=仅「删除」菜单）、鼠标右键（同款，仅手势机 IDLE 且非只读响应、空白拒绝）、桌面双击（合并=单元菜单，保留）。v3 菜单构成：单元浮窗标题=「合并单元」，按钮=✂拆开 + 胶囊/单编号（两样式自动生成）+ 删除 + ✕。「删除」= M.removeDancer（与名册同源），清理 merges/groups 引用、positions 键===dancers id、可 undo；单元删除=两人都删。规格外最小补充：**拆开后清除该单元 selection**（防原子选择残留导致叠落误弹合并确认，R-06 断言之）。
**v3 共享数据不变式（R 组每条动线断言）**：① 各队形 `positions` 键排序 === `dancers` id 排序；② `merges` 引用有效（a/b ∈ dancers、a≠b、样式 ∈ UNIT_STYLES、无重复键）；③ **`groups` 引用有效（v3 新：memberIds ⊆ dancers、组 id 唯一）**——原 v2 的 `proj.pairs.every(...)` 不变式随 pairs 退役废止。

## 3.6 GR 组 —— RTS 编组动线（v3 新增；project.groups 纯选择辅助）

**背景**：舞对绑定退役后新增 RTS 式编组：`project.groups=[{id,name,memberIds[]}]`，纯选择辅助，
**可与合并单元交叉叠加**（组成员若在合并单元中，组选择按单元原子规则展开为整单元两人），不改变渲染/数据语义。
入口：① 键盘 **Ctrl/Cmd+1..9=把当前选择存入编组 N（N 已存在则覆盖）**、**1..9=选中编组 N（替换选择）**、**Shift+1..9=追加编组 N**（全部按 `e.code` Digit1..9 判定）；② 右侧面板「编组」tab（组行点击/「选择」按钮=选中、重命名、删除组——**删除组≠删除舞者**、＋存为编组）；③ 名册每行编组 chips（点击加入/移出，一名舞者可属多组）；④ 新建项目「初始编组」：`gender`（默认，自动建「男士/女士」两组）| `none`（无组）。

## 4. 执行与判定规范

1. **顺序（v3）**：L0 门禁 → L0 元测试 → L1 → R 组 → **GR 组** → L2。任何 L0 失败：不出业务结论。
2. **失败即停**：记录证据包（用例 id、步骤、四类检查点结果、positions/merges/groups 快照、失败帧截图）。
3. **泄漏即停**：任一动线后 `debugPointers()` 非空 = 缺陷，修复后该组从头重跑。
4. **SCREEN 失败 = 环境故障**：重建标签，从 L0 重来；不产出应用结论。
5. **回归红线**：node 单测全绿（阈值随用例演进，**当前 101/101**，以 lab/run-l2.mjs 红线阈值为准）。
6. **证据包**：每条结论必须能引用 `{用例ID, 步骤, 四类检查点结果, 数据快照, 截图路径}`。

## 5. 已知局限（诚实声明）

- isTrusted 无法模拟：OS 级输入等价性靠"事件链建模 + 人工按同清单执行"双兜底；
- 人工目检仅用于 SCREEN 层的最终确认，判定以自动比对为准；
- 长按/驻留/双击为时序敏感用例，注入器显式控制时序并测量验证（I7）；
- GR 快捷键为 `e.code` 合成事件（真实键盘 Shift+数字产生的 `!@#` 字符差异由 e.code 判定吸收，注入器显式传 `code: 'DigitN'`）。
